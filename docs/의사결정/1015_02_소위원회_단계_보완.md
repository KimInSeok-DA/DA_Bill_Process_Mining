# 1015_02 소위원회 단계 보완

- 상태: 확정 (사용자 결정 A, 2026-10-15). 여러 줄 의안의 처리는 이벤트 로그 결정 문서에서 정한다(6절)
- 코드: `src/collect.py --service subcommittee` → `data/raw/TVBPMCONFINFO/AGE22_20261015/`
- 배경: [1015_01](1015_01_날짜필드_정의.md) 화면 대조에서 소관위 상정 → 처리 사이의 실제 심사가 대부분 **소위원회**에서 일어나는 것을 확인했다. 지금 쓰는 「국회의원 발의법률안」 API에는 소위 날짜가 없다

## 1. 문제

| 확인한 것 | 근거 |
|---|---|
| 소관위 상정 날 소위에 회부되고, 소위가 심사·의결한 뒤 전체회의가 처리한다 | A·B·F·G 화면의 소관위 회의정보("상정/…/소위회부") |
| 대기의 큰 부분이 소위 안에 있다 | B: 소위 회부 2024-11-19 → 소위 상정·처리 2026-09-03(약 1년 9개월). 소위 처리 → 전체회의 처리는 13일 |
| 계류 의안도 소위에 묶여 있다 | D: 2025-09-08 소위 회부 뒤 소위 상정 전 |
| 소위에 바로 회부되는 경우가 있다 | G: 국회법 제58조제4항, 소관위 상정일이 비어 있음 |

지금 데이터로 이벤트 로그를 만들면 "소관위 상정 → 소관위 처리" 구간 하나에 다음이 섞인다.
- 소위 상정까지 기다린 시간(실제 병목으로 추정)
- 소위 심사 시간
- 소위 처리 뒤 전체회의까지 걸린 시간

그래서 "소관위에서 오래 멈춘다"까지만 말할 수 있고, 그 안의 어디인지는 말할 수 없다.

| 본회의 상정일 | 대부분 의결일과 같은 날이라 효과 작음 | 낮음 |

## 3. 찾은 데이터: 「소위 심사정보(법률안)」

- 요청 주소 `https://open.assembly.go.kr/portal/openapi/TVBPMCONFINFO`(사용자가 서비스 페이지 확인, 2026-10-15)
- 필수 인자 `AGE`. 선택 인자 `BILL_NO`, `BILL_ID`, `ENROLL_TYPE`(소위 직접 회부 여부). 한 번에 최대 1,000건
- AGE=22 전체 18,324행(샘플 응답 기준) → **약 19번 호출로 전부 받을 수 있다**(의안별 호출 불필요)
- 출력: `BILL_ID`, `BILL_NO`, `COMMITTEE_NAME`, `SUB_COMMITTEE_NAME`, `SUBMIT_DT`(소위 회부일), `PRESENT_DT`(소위 상정일), `PROC_DT`(소위 처리일), `PROC_RESULT_CD`, `ENROLL_TYPE`, `CONF_BIGO` 등
- `BILL_ID`가 있어 지금 데이터와 바로 연결된다

## 4. 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 소위 데이터를 추가 수집해 이벤트 로그 v1에 넣는다 | 병목을 "소위 상정 대기 / 소위 심사 / 전체회의 처리 대기"로 쪼갤 수 있다. 호출 약 19번, 화면 7건 일치 확인 | 한 의안에 소위 행이 여러 개일 수 있음(재회부 등), 연결률·중복을 확인해야 함. 이벤트 로그 결정이 하나 늘어남 |
| B | v1은 지금 데이터만, 소위는 v2 | 일정이 가장 안전 | 가장 큰 병목을 "소관위 안"까지만 말할 수 있음 |
| C | 소위를 넣지 않고 한계로만 적는다 | 가장 단순 | 프로세스 마이닝의 핵심(병목 위치)이 약해짐 |

- 정부이송·공포일: 가결 뒤 단계라 핵심 질문(어디서 멈추나)과 거리가 있어 이번에는 넣지 않는 것을 제안(필요하면 `ALLBILL` 확인)

## 5. 결정

**A: 소위 데이터를 추가 수집해 이벤트 로그 v1에 넣는다.** 정부이송·공포일은 넣지 않는다.

결정 과정: AI가 화면 대조 중 소위 단계가 빠진 것을 보완사항으로 제기 → 사용자가 서비스 페이지를 열어 요청 주소·인자를 확인 → AI가 7건을 API로 조회해 화면과 일치 확인, A 추천 → 사용자 A 결정

근거:
1. 분석의 핵심 질문(어디서 가장 오래 멈추나)에 직접 답한다. 소관위 구간을 소위 상정 대기·소위 심사·전체회의 처리 대기로 나눌 수 있다
2. 비용이 작다(호출 19번)
3. 화면 7건과 값이 모두 맞았다

바꾸는 조건: 여러 줄 의안 처리가 복잡해 일정이 밀리면, v1은 단일 행 의안(소위 기록이 있는 의안의 97.3%)만 소위 단계를 넣고 나머지는 표시만 한다
