# 1016_10 소위는 같은 법률안을 몇 번 심사하나: 위원회 회의정보

- 상태: 확정 (사용자 결정, 2026-10-16 선택 과제 순서 "진행하자": 회의정보 API 확인 → 지연 법률안 특징 → OCEL → 회의정보 → 164건 → CSV 공개. 회의정보는 수집 시간이 길어 지연 특징과 함께 먼저 시작했다. "그래 진행하자"로 이 문서 작성)

- 미리 밝혀 둘 것: 정의를 쓰기 전에 수집 중인 파일(약 2,400건)에서 **값의 종류만** 봤다. 회의 이름은 "제N회 국회(임시회·정기회) 제N차 전체회의 / 소위회의" 두 가지, 회의 결과(`JRCMIT_CONF_RSLT`)는 상정·제안설명·검토보고·대체토론·소위회부·축조심사·의결·소위심사보고·찬반토론 9가지였고, 자료 없음(INFO-200)이 3건 있었다. 법률안 한 건(무작위 1건)의 회의 기록 12행을 열어 봤다. 상정 횟수의 분포나 비율은 보지 않았다
- 입력: 「의안 위원회심사 회의정보 조회」(`BILLJUDGECONF`, 2026-10-16 조회) `data/raw/BILLJUDGECONF/AGE22_20261016/<BILL_ID>.json`, 이벤트 로그 v2(`data/processed/event_log.csv`, 2026-10-15 조회 원본)
- 코드: `src/collect.py --service conf` → 위 원본, `src/meetings.py` → `outputs/tables/meetings_*.csv`, `outputs/figures/fig14_meetings.png`, `outputs/meetings_results.json`

## 1. 왜 하나

지금까지의 이벤트 로그는 단계마다 **첫 날짜 하나**만 쓴다(소위 상정일, 소위 처리일 등). 그래서 "소위 상정 → 소위 처리"에 시간이 걸리면, 그것이 한 번 상정된 뒤 기다린 것인지, 여러 번 상정되어 심사가 이어진 것인지(반복 심사) 구분할 수 없었다. 회의정보 API는 법률안이 다뤄진 **회의마다** 기록을 준다. 이것으로 소위가 같은 법률안을 몇 번의 회의에서 다루는지를 본다. 프로세스 마이닝에서 같은 활동이 되풀이되는 **재작업(rework)** 을 찾는 분석에 해당한다.

## 2. 수집

- API: 「의안 위원회심사 회의정보 조회」, 요청 코드 `BILLJUDGECONF`. 명세서(xlsx)로 확인했고 `BILL_ID`가 필수다(인자 없이 또는 대수만으로 부르면 ERROR-300). 그래서 **법률안마다 한 번씩** 부른다
- 대상: 22대 원안(의원·정부) 중 「소위 심사정보」에 소위 상정일(`PRESENT_DT`)이 있는 법률안 **7,847건**. 반복 심사는 소위에 상정된 뒤에만 생기므로 이 범위로 좁혔다(사용자에게 보고한 추천안). 나중에 범위를 넓혀도 받은 파일은 다시 부르지 않는다
- 시험 호출: 2101754(21대, 화면 대조에 쓴 의안) 17행, 회의 7번. 의안정보시스템 화면의 "소관위 회의정보" 표와 같았다
- 출력 필드: ERACO, BILL_ID, BILL_NO, BILL_NM, PPSR, PPSL_DT, JRCMIT_CONF_NM(회의 이름), JRCMIT_CONF_DT(회의 날짜), JRCMIT_CONF_RSLT(그 회의에서 한 일). 회의 하나에서 한 일(상정·축조심사·의결 등)이 **한 행씩** 나온다
- 수집 속도: 한 건에 약 2.5초(호출 간격 포함), 전체 약 5시간 20분
- 대조(수집 코드): 파일 수 = 대상 수, 한 페이지(1,000행)를 넘는 응답 없음, 응답의 BILL_ID = 요청한 BILL_ID
- **조회일 차이:** 이 원본은 2026-10-16, 이벤트 로그 원본은 2026-10-15에 조회했다. 맞추기 위해 **회의 날짜가 2026-10-15보다 뒤인 행은 버린다**(버린 행 수를 8절에 적는다)

## 3. 정의

| 용어 | 정의 |
|---|---|
| 소위회의 행 | 회의 이름에 "소위회의"가 들어 있는 행. 회의 이름에 소위원회 이름은 없다(법률안의 소관위원회 안 소위로 본다) |
| **소위 상정 횟수** | 소위회의 행 중 결과가 "상정"인 행의 **서로 다른 회의 날짜 수**. 같은 날 회의 이름이 두 개(예: 제1차·제2차)여도 하루로 센다(회의가 자정을 넘겨 차수가 바뀌는 경우를 한 번으로 보기 위함) |
| **반복 심사** | 소위 상정 횟수 2회 이상 |
| 재상정 간격 | 첫 소위 상정 날짜 → 두 번째 소위 상정 날짜 날수 |
| 자료 없음 | 응답이 INFO-200(해당 자료 없음)인 법률안. 분석에서 빼고 건수만 적는다 |
| 소위 상정 없음 | 회의 기록은 있지만 "소위회의 + 상정" 행이 없는 법률안. 분석(R1～R3)에서 빼고 정합성 확인(C)에서 따로 센다 |

- 이벤트 로그 v2는 바꾸지 않는다. 회의 단위 기록은 OCEL(1016_12)에서 "회의"를 객체로 넣을 때 쓴다

## 5. 가설과 판정 기준

**동점·값 없음 처리를 함께 정한다**(1016_09 T3, 1016_11에서 빠뜨린 것).

| | 가설 | 지지 판정 기준 | 동점·값 없음 |
|---|---|---|---|
| R1 | 반복 심사는 흔하다 | 소위에 상정된 원안 중 반복 심사(2회 이상) 비율 **≥ 20%** | 정확히 20%면 지지. 기준 20%("다섯 건 중 한 건")는 어림값이고 근거가 되는 이전 수치는 없다 |
| R2 | 반복 심사는 연달아 열린 회의가 아니라 한참 뒤에 이어진다 | 반복 심사 원안의 재상정 간격 중앙값 **≥ 90일** | 정확히 90일이면 지지. 반복 심사 원안이 30건 미만이면 판정 불가 |
| R3 | 같은 법 법률안이 아주 많이 몰린 원안은 반복 심사가 더 많다 | 같은 법 법률안 50건 이상 원안의 반복 심사 비율 **>** 혼자(1건) 원안의 비율 | 두 비율이 같으면 지지하지 않음. 두 집단 중 하나라도 30건 미만이면 판정 불가 |

- R2의 치우침: 2회 이상 상정된 법률안만 보므로, 최근에 처음 상정되어 아직 두 번째를 기다리는 법률안은 빠진다. 이 치우침은 간격을 **짧게** 만드는 쪽이라 가설에 불리하다. 그래서 중앙값이 90일 이상이면 가설을 지지하는 결론은 보수적이다. 생존분석(KM)은 쓰지 않는다(첫 회의에서 바로 의결되는 법률안은 두 번째 상정이 영영 없어, "아직 기다림"으로 다루기 어렵다)
- R3의 "같은 법 법률안 수"는 1016_11의 F1과 같은 규칙·같은 집단(22대 원안 전체에서 센 수)이다
- 보조(판정 없음): 소위 상정 횟수 분포(1·2·3·4회 이상), 제안자별 반복 심사 비율, 소위 상정 1회 중 그 회의에서 "의결"까지 간 비율, 위원회별 반복 심사 비율(30건 이상 위원회)

## 6. 검증

- 교차 검증: 원본 JSON을 DuckDB `read_json`으로 직접 읽어 SQL로 소위 상정 횟수·반복 심사 비율·재상정 간격 중앙값·R3 두 비율·C 일치 비율을 다시 계산한다(`cross_check.py` ⑭). pandas 분석 코드를 쓰지 않는다
- 화면 대조 3건: 소위 상정 1회, 2회, 3회 이상에서 한 건씩 골라 의안정보시스템 화면의 "소관위 회의정보"와 대조한다. 결과를 보고 고르지만 데이터가 맞는지 확인하는 용도라 판정에는 영향이 없다

## 7. 바꾸는 조건과 한계

- 회의 이름에 "소위회의"가 아닌 다른 형태(예: 특정 소위 이름)가 나오면 정의를 고치고 이 문서에 적는다
- "상정"됐지만 실제로는 다루지 못하고 넘어간 경우(상정만 있고 축조심사·의결이 없는 회의)도 한 번으로 센다. 상정 뒤 실제 심사가 있었는지는 보조로 "상정만 있는 회의" 비율을 적는다
- 반복 심사가 많다는 것은 처리 방식에 관한 사실이지, 일을 잘하거나 못한다는 평가가 아니다. 쟁점이 많은 법률안일수록 여러 번 다루는 것이 자연스럽다
- 회의 이름에 소위원회 이름이 없어, 한 위원회에 소위가 여러 개일 때 어느 소위인지 구분하지 못한다

### 결과에서 얻은 것

1. 소위에 상정된 원안의 절반이 두 번 이상 상정된다. 지금 이벤트 로그는 첫 상정만 써서 이 재작업이 보이지 않았다
2. 다시 상정되는 간격은 대부분 짧다(절반이 7일 안, 4분의 3이 64일 안). 반복 심사의 다수는 같은 회기 안에서 며칠 간격으로 이어지는 연속 심사다. 다만 4분의 1은 두 달 넘게 뒤에 다시 상정된다
