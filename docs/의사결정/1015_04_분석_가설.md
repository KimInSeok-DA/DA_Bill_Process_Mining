## 1. 질문

**의안은 어디서, 왜 오래 멈추나?**

이벤트 로그를 만들며 이미 확인한 사실은 가설로 쓰지 않고 배경으로만 쓴다.
- 처리된 의안의 82%(4,308/5,249)가 대안반영폐기다
- 소관위 상정 뒤 아직 처리 전인 의안이 11,242건이다
- 소위 상정 → 처리 중앙값은 0일, 소위 처리 → 소관위 처리는 2일이다(1015_03 민감도 점검)

## 2. 공통 정의

| 항목 | 정의 |
|---|---|
| 구간 대기 | 같은 의안에서 활동 A의 첫 날짜 → 활동 B의 첫 날짜(일) |
| 관찰된 대기 | A와 B가 모두 있는 의안의 대기. 중앙값과 상위 10%(90분위) |
| 계류(조회일 기준) | A는 있고 B는 없는 진행 중 의안. 건수와 조회일(2026-10-15)까지 경과일 중앙값 |
| 두 값을 함께 보는 이유 | 관찰된 대기만 보면 빨리 끝난 의안만 남아 짧게 보인다(중도절단, 1015_03 2-1). 계류 건수가 많고 경과일이 길면 실제 대기는 관찰값보다 길다 |
| 진행 중 상태 | 진행 중 의안의 마지막 활동으로 지금 기다리는 단계를 정한다(예: 마지막이 소위 회부면 "소위 상정 대기") |

- 생존분석(Kaplan-Meier)으로 중도절단을 보정한 중앙값도 가능하다. 이번에는 설명하기 쉬운 "관찰값 + 계류" 두 값으로 보이고, 결론이 두 값에서 엇갈릴 때만 추가한다

## 3. 가설과 판정 기준

| | 가설 | 지표 | 지지 판정 기준(미리 정함) |
|---|---|---|---|
| H1 | 가장 오래 멈추는 곳은 소위 심사가 시작되기 전(소위 회부 → 소위 상정)이고, 심사가 시작되면 빨리 끝난다 | 표준 구간별 관찰 대기(중앙값·90분위)와 계류(건수·경과일), pm4py 성능 지도 | 소위 회부 → 소위 상정이 관찰 중앙값과 계류 건수 **둘 다** 모든 구간 중 1위 |
| H2 | 처리의 중심은 비슷한 법안을 묶어 위원회 대안으로 처리하는 것이고, 그래서 같은 날 같은 위원회에서 여러 의안이 함께 처리된다 | (위원회, 날짜)별 소관위 처리 건수(묶음 크기) 분포, 결과별 변형 상위 10개 | 소관위 처리 이벤트의 과반이 2건 이상 묶음에 속함 |
| H3 | 진행 중 의안의 대부분은 소위 상정 전 단계에 머물러 있다 | 진행 중 의안의 현재 대기 단계 분포와 경과일 | "소위 상정 대기"가 진행 중 의안의 과반 |
| H4 | 법사위 체계·자구 심사는 병목이 아니다 | 소관위 처리 → 법사위 회부 → 법사위 처리 → 본회의 구간 대기 | 법사위 회부 → 법사위 처리 관찰 중앙값 30일 이하이고, 이 구간 계류가 진행 중 의안의 5% 미만 |
| H5 | 대기시간은 위원회마다 크게 다르다 | 상임위원회별 소위 회부 → 소위 상정 관찰 중앙값, 소위 회부 의안 중 소위 상정까지 간 비율 | 관찰 중앙값의 최대/최소가 2배 이상 |
| H6 | 처리는 특정 시기에 몰린다 | 월별 소관위 처리·끝 활동 건수 | 끝 활동 건수 상위 3개월이 전체의 30% 이상(고르게 퍼지면 약 12%) |

- 판정은 "지지 / 지지하지 않음"으로만 쓰고, 기준에 걸치면 그대로 적는다
- 해석은 절차까지만 쓰고, 정치적 평가는 하지 않는다. H5는 "어느 위원회가 느리다"는 평가가 아니라 차이의 크기와 분포만 보인다

## 4. H5 위원회 이름 묶기

### 확인한 것 (대기 결과를 보기 전에 이름·기간·처리 상태만 확인)

| 옛 이름 → 새 이름 | 옛 이름 의안 | 그중 처리 완료 | 새 이름 의안 | 그중 처리 완료 |
|---|---|---|---|---|
| 기획재정위원회 → 재정경제기획위원회 | 439 | 100% | 1,517 | 5% |
| 환경노동위원회 → 기후에너지환경노동위원회 | 145 | 100% | 1,799 | 19% |
| 여성가족위원회 → 성평등가족위원회 | 38 | 100% | 230 | 21% |

- 새 이름이 2024-06(22대 개원 직후) 기록부터 붙어 있다. 원 시스템이 **개편 뒤에도 진행 중인 의안에는 새 이름을 소급해 붙이고, 개편 전에 끝난 의안에는 옛 이름을 남긴 것**으로 보인다
- 그래서 이름이 위원회를 구분하는 것이 아니라 "개편 전에 처리가 끝났는가"를 구분한다

### 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 묶는다** | 옛 이름을 새 이름으로 바꿔 한 위원회로 본다(3쌍) | 같은 위원회의 의안이 처리 상태와 상관없이 한곳에 모인다. 위원회 수가 상임위 17개로 맞는다 | 개편으로 소관(맡은 법률)이 바뀐 부분이 섞인다(예: 기후에너지환경노동위원회는 에너지 소관이 추가됨) |
| B. 묶지 않는다 | 이름 그대로 20개로 본다 | 원본 그대로, 손대지 않음 | 옛 이름 쪽은 완료 의안만, 새 이름 쪽은 진행 중 의안 위주라 **처리 상태 차이가 위원회 차이처럼 보인다**. 옛 이름 쪽은 표본도 작다(38～439건) |
| C. 개편 시점으로 나눈다 | 날짜 기준으로 개편 전/후를 나눈다 | 소관 변화 전후를 구분 | 원 시스템이 이름을 소급해 붙여서 이름으로는 시점을 알 수 없고, 개편 날짜를 따로 확인해야 함. 일정 대비 이득이 작음 |

### 결정: A(묶는다)

- 근거 1: B를 택하면 옛 이름은 처리 완료 100%, 새 이름은 5～21%라, 위원회 비교가 사실상 "완료 의안 대 진행 중 의안" 비교가 된다. H5의 질문(위원회마다 다른가)에 답할 수 없다
- 근거 2: 이름만 바뀐 같은 상임위원회다. 의안을 맡는 소위·절차가 이어진다
- 근거 3: 소관 변화(에너지 이관 등)는 묶어도 남는 한계로 적는다. 산업통상자원중소벤처기업위원회는 소관 일부가 넘어갔을 뿐 이름이 그대로라 따로 둔다
- 특별위원회 5개(기후위기, 정치개혁 등)는 한시 조직이고 의안이 적어(5～48건) 위원회 비교에서 빼고 전체 집계에만 넣는다
- 위원회는 이벤트의 `committee`(그 단계를 맡은 위원회)로 본다. 재회부 의안은 단계마다 맡은 위원회가 다를 수 있다
- 바꾸는 조건: 개편 날짜를 확인해 개편 전후 비교가 분석 질문이 되면 C로 바꾼다

| 지표 | 범위 |
|---|---|
| 관찰 중앙값 | 3～150일(50배) |
| KM 중앙값 | 8～620일. 7개 위원회는 관찰 기간 안에 절반 넘게 상정 전이라 정의 안 됨 |

- **관찰 중앙값과 KM 중앙값의 순서가 크게 다르다.** 관찰 중앙값이 가장 짧은 위원회(3일)의 KM 중앙값은 349일이고 상정 도달 비율은 51%다. 상정된 의안은 빨리 상정됐지만, 절반은 아직 상정 전이라는 뜻이다. 위원회를 관찰 중앙값만으로 비교하면 반대 결론이 날 수 있다

### H6: 월별 처리

- 끝 활동 상위 3개월: 2025-12 662건, 2024-12 429건, 2026-01 366건 → 27.8%(기준 30% 미달)
- 미리 적은 "고르게 퍼지면 약 12%"는 24개월을 가정한 값이었다. 실제 관찰 기간은 30개월이라 10%다
- 월별 편차는 크다(0～662건). 상위 두 달이 모두 12월이지만, 원인(정기회 일정 등)은 이 데이터로 확인하지 않았다
- 보조 사실(판정에 쓰지 않음): 소관위 처리로 세면 상위 3개월(2025-11 810건, 2026-03 477건, 2026-04 457건)이 33.2%다. 미리 정한 지표는 끝 활동이라 판정은 바꾸지 않는다

### 결과에서 얻은 것

1. 병목은 **소위 심사가 시작되기 전**이다. 회부된 의안의 절반 넘게 1년 넘게 상정되지 않는다(KM 531일, 계류 9,667건)
2. 처리 단위는 의안 1건이 아니라 **묶음**이다. 위원회는 한 회의에서 수십 건을 대안으로 묶어 처리한다(의안 기준 묶음 크기 중앙값 41건)
3. **끝난 의안만 보면 병목을 놓친다.** 관찰 중앙값으로는 소위 상정 대기가 21일로 3위였고, 위원회 비교는 순서가 뒤집혔다. 진행 중 의안을 함께 보는 것이 프로세스 마이닝에서 필수다

### 한계

- 일 단위 날짜라 같은 날 단계 사이 대기는 0일이다
- KM은 관찰을 멈춘 의안과 계속 관찰한 의안의 대기 경향이 같다고 가정한다. 철회·대안 흡수처럼 다른 결과로 끝나는 의안을 중도절단으로 다뤘다
- 위원회 묶기 뒤에도 소관 변화(에너지 이관 등)가 섞여 있다
- 대기가 긴 이유(법안 내용, 정치 일정 등)는 이 데이터로 설명하지 않는다
