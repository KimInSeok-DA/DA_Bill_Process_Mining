# 1016_08 적합성 검사(conformance checking)

- 상태: 확정 (사용자 결정, 2026-10-16). 추천안대로: 규범 모델 + 정렬이 주 분석, 규칙(SQL)은 교차 검증. 끝난 법률안은 정렬 적합도, 처리 중인 법률안은 지금까지의 이탈
- **이 문서의 정의·가설·판정 기준은 결과를 보기 전에 썼다.** 결과는 7절에 덧붙인다
- 미리 밝혀 둘 것: 1015_04에서 처리된 법률안의 경로 분포(변형 상위 10개)를 이미 봤다. 그래서 C1의 결과를 어느 정도 짐작할 수 있다. 판정 기준은 그 전에 제안·승인된 값 그대로 쓴다
- 입력: `data/processed/event_log.csv`(v2), 원안(의원·정부) 20,419건
- 코드: `src/conformance.py` → `outputs/tables/conf_*.csv`, `outputs/figures/fig11_conformance.png`, `outputs/conformance_results.json`

## 1. 무엇을 하나

적합성 검사는 "이렇게 처리돼야 한다"는 절차 모델을 정해 두고, 실제 기록이 그 모델과 얼마나 맞는지, 어디서 벗어나는지를 재는 분석이다. 지금까지의 분석(1015_04)이 "어디서 오래 멈추나"였다면, 이번에는 "정해진 절차를 얼마나 따르나"를 본다.

## 2. 정상 절차 모델 (원안)

국회법의 표준 경로를 **상태 전이도**로 정의한다. 상태 전이도는 페트리넷의 한 종류라 pm4py 정렬(alignment)에 그대로 쓸 수 있다.

| 지금 상태 | 허용된 다음 활동 → 다음 상태 |
|---|---|
| 시작 | 제안 → 제안됨 |
| 제안됨 | 소관위 회부 → 회부됨 |
| 회부됨 | 소관위 상정 → 상정됨 |
| 상정됨 | 소위 회부 → 소위 회부됨 |
| 소위 회부됨 | 소위 상정 → 소위 심사 중 |
| 소위 심사 중 | 소위 상정(다시 상정, 반복 허용) → 소위 심사 중 / 소위 처리 → 소위 처리됨 |
| 소위 처리됨 | 소관위 처리 → 소관위 처리됨 |
| 소관위 처리됨 | 법사위 회부 → 법사위 회부됨 / 대안반영폐기·수정안반영폐기·폐기 → 끝 |
| 법사위 회부됨 | 법사위 상정 → 법사위 상정됨 |
| 법사위 상정됨 | 법사위 처리 → 법사위 처리됨 |
| 법사위 처리됨 | 가결·부결·폐기 → 끝 |
| 끝이 아닌 모든 상태 | 철회 → 끝(제안자는 언제든 철회할 수 있음) |

- 모델에 넣지 않은 것은 모두 "이탈"이다. 법이 허용한 예외 경로도 일부러 모델에 넣지 않고, 이탈로 잡은 뒤 예외 유형으로 분류한다(4절). 그래야 "표준 경로를 얼마나 따르나"와 "벗어난 것이 법이 허용한 예외인가"를 나눠 볼 수 있다

## 3. 지표

| 대상 | 방법 | 지표 |
|---|---|---|
| 끝난 원안 5,474건 | pm4py 정렬: 실제 경로를 모델의 가장 가까운 경로에 맞추며, 모델에 없는 활동(로그 이동)과 실제에 없는 모델 활동(모델 이동)을 센다 | 경로별 적합도(0～1, 1 = 완전 일치), 완전 적합 비율, 이탈 유형 |
| 처리 중인 원안 14,945건 | 상태 전이도를 따라가며, 처음으로 허용되지 않은 활동이 나온 곳을 찾는다(아직 끝나지 않았으므로 "빠진 단계"는 이탈로 보지 않음) | 지금까지 이탈한 비율, 이탈 유형 |
| 교차 검증 | 같은 모델을 정규식으로 옮겨 SQL(DuckDB)로 경로 문자열을 검사 | 완전 적합 건수, 처리 중 이탈 건수, 예외 유형별 건수가 두 방법에서 같은지 |

## 4. 예외 유형 (이탈 경로에 붙이는 이름)

이탈한 경로에 아래 규칙을 순서대로 적용해 첫 번째로 맞는 유형을 붙인다. 앞의 다섯 가지가 법이 허용한 예외다.

| 순서 | 유형 | 규칙 | 근거 |
|---|---|---|---|
| 1 | 재회부 | "소관위 재회부"가 있거나, 소위 회부가 두 번 이상이고 맡은 위원회가 바뀜 | 위원회 개편·특별위원회(1015_03 4절) |
| 2 | 소위 직접 회부 | 소관위 상정 없이 소위 회부가 오거나, 소관위 상정이 소위 처리 뒤에 옴 | 국회법 제58조제4항(1015_03 4절) |
| 3 | 신속처리 | 소관위 처리 없이 법사위 회부가 옴 | 국회법 제85조의2, `심사미료` 날짜 제외(1015_01 G) |
| 4 | 예산부수 자동부의 | 소관위 처리 없이 가결 | 국회법 제85조의3(1015_01 F) |
| 5 | 법사위 소관 | 법사위 단계 없이 가결·부결되고 소관위가 법제사법위원회 | 소관위와 체계·자구 심사 기관이 같음(1015_01 E) |
| 6 | 소위 생략 | 소위 기록 없이 소관위 처리 | 법이 정한 예외는 아님(국회법 제58조는 소위 심사를 원칙으로 함) |
| 7 | 그 밖 | 위에 해당하지 않음 | 경로를 직접 확인해 적는다 |

## 5. 가설과 판정 기준

| | 가설 | 지지 판정 기준 |
|---|---|---|
| C1 | 끝난 원안의 대부분은 표준 절차를 따른다 | 완전 적합(적합도 1.0)이 90% 이상 |
| C2 | 표준 절차에서 벗어난 경우의 대부분은 법이 허용한 예외다 | 이탈한 끝난 원안 중 유형 1～5가 80% 이상 |

## 6. 바꾸는 조건

- 예외 유형 규칙으로 설명되지 않는 이탈이 많으면, 그 경로를 화면 몇 건으로 확인하고 유형을 추가한다(추가하면 이 문서에 기록하고, 판정은 처음 규칙 기준으로도 함께 적는다)

### 교차 검증

- 같은 모델을 정규식으로 옮겨 SQL(DuckDB)로 경로 문자열을 검사하고, 예외 유형 규칙도 SQL로 따로 작성했다. 완전 적합 3,979건, 처리 중 표준 절차 13,583건, 유형별 건수 등 16항목 모두 일치(`cross_check.py` ⑪, 전체 326항목)

### 결과에서 얻은 것

1. 표준 경로만이 "정상"은 아니다. 법이 허용한 소위 직접 회부가 끝난 원안의 5분의 1을 차지한다. 업무 흐름을 관리할 때 정상 경로를 하나로 두면 이 경로가 모두 "이탈"로 잡혀 경보가 너무 많아진다
2. 법이 허용하지 않은 듯 보이는 이탈(소위 생략·그 밖, 끝난 원안의 2.6%)은 대부분 기록 누락 패턴이다. 적합성 검사는 절차 점검뿐 아니라 **데이터 품질 점검** 도구로도 쓸 수 있다
