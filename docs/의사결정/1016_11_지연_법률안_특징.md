# 1016_11 어떤 법률안이 소위 상정까지 오래 기다리나

- 상태: 확정 (사용자 결정, 2026-10-16 선택 과제 순서 "진행하자": 회의정보 API 확인 → 지연 법률안 특징 → OCEL → 회의정보 → 164건 → CSV 공개). 방법은 "단순한 방법 우선"(집단별 KM과 위원회 안 비교, 회귀는 쓰지 않음)
- **이 문서의 정의·가설·판정 기준은 결과를 보기 전에 썼다.** 결과는 7절에 덧붙인다
- 미리 밝혀 둘 것: 정부안 대 의원안의 전체 차이(Q7: 202일 대 531일)와 위원회별 차이(H5: 8～635일)는 이미 알고 있다. 법률안 종류별 건수(일부개정 18,988 · 제정 1,310 · 전부개정 86 · 폐지 35)와 같은 법을 고치는 법률안 수의 분포(법 2,577개, 법당 중앙값 2건)는 봤지만, 집단별 대기일은 보지 않았다
- 입력: `data/processed/event_log.csv`(v2), 법률안 이름은 「법률안 심사 및 처리(의안검색)」 원본(`BILL_NAME`)
- 코드: `src/delay_factors.py` → `outputs/tables/delay_*.csv`, `outputs/figures/fig13_delay_factors.png`, `outputs/delay_results.json`

## 1. 무엇을 하나

지금까지는 "어디서 멈추나"를 봤다(소위 회부 → 소위 상정, 기다리는 법률안까지 포함한 중앙값 516일). 이번에는 같은 구간에서 **어떤 법률안이 더 오래 기다리나**를 본다. 프로세스 마이닝의 원인 분석(root cause analysis)에 해당하지만, 이 데이터로는 원인이 아니라 **관련**까지만 말한다.

## 2. 대상과 대기 정의

- 대상: 22대 원안(의원·정부) 중 소위 회부 기록이 있는 법률안(H1 "소위 회부 → 소위 상정"의 대상과 같음)
- 대기: 소위 회부 → 소위 상정 날수. 아직 상정되지 않았으면 조회일, 다른 결과로 끝났으면 그 날짜에서 중도절단. 22대 분석(`analysis.py`)의 `interval`·`km_median`을 그대로 쓴다
- 집단 비교는 KM 중앙값으로 한다. 중앙값이 없으면(절반 넘게 아직 기다림) "관찰 기간보다 길다(∞)"로 본다

## 3. 특징 (소위 회부 시점에 알 수 있는 것만)

| 특징 | 정의 | 집단 |
|---|---|---|
| F1 같은 법을 고치는 법률안 수 | 법 이름이 같은 22대 원안 수(자기 포함). 법 이름은 법률안 이름에서 " 일부개정법률안·전부개정법률안·폐지법률안" 꼬리를 떼고, 그런 꼬리가 없으면(제정법안) 끝의 "안"만 뗀다. 예: "○○법 일부개정법률안" → "○○법", "○○법안" → "○○법", "○○에 관한 법률안" → "○○에 관한 법률" | 1건(혼자) / 2～4 / 5～9 / 10～49 / 50건 이상 |
| F2 법률안 종류 | 이름에 "일부개정" → 일부개정, "전부개정" → 전부개정, "폐지" → 폐지, 그 밖 → 제정 | 일부개정 / 제정 / 전부개정·폐지 |
| F3 제안자 | 의원 / 정부 | 의원 / 정부 |

- F1은 22대 전체 기간의 건수다. 나중에 들어온 같은 법 법률안도 센다. 위원회는 같은 법 법률안을 함께 상정하는 경우가 많아(H2 묶음 처리), 뒤에 비슷한 법률안이 들어오면 앞의 법률안도 함께 상정될 수 있기 때문이다. 그래서 F1은 "소위 회부 시점에 알 수 있는 것"이 엄밀히는 아니다(7절에 한계로 적는다)
- 쓰지 않은 것: 공동발의자 수(법정 최소 10명 근처에 몰려 있음, 중앙값 10, 사분위 9～12), 정당·의원 이름(정치적 평가로 읽힐 수 있음)

## 4. 위원회 안 비교

특징과 위원회는 서로 얽혀 있다(예: 같은 법 법률안이 많은 위원회가 원래 빠를 수 있음). 그래서 전체 비교와 함께, **같은 위원회 안에서** 두 집단을 비교해 같은 방향인 위원회가 몇 개인지 센다.
- 위원회는 H5와 같다(맡은 위원회, 개편 전후 이름 묶음, 특별위원회 제외)
- 비교하는 두 집단이 각각 30건 이상인 위원회만 센다. 그런 위원회가 5개 미만이면 위원회 안 비교는 "판정 불가"로 두고 전체 비교로만 판정한다

## 5. 가설과 판정 기준

| | 가설 | 지지 판정 기준(둘 다 만족) |
|---|---|---|
| D1 | 같은 법을 고치는 다른 법률안이 없는 "혼자" 법률안은, 같은 법 법률안이 10건 이상인 법률안보다 오래 기다린다 | (a) 혼자의 KM 중앙값 ≥ 10건 이상(10～49와 50건 이상을 합침)의 2배 (b) 위원회 안 비교에서 과반이 같은 방향 |
| D2 | 제정법안은 일부개정법안보다 오래 기다린다 | (a) 제정의 KM 중앙값 ≥ 일부개정의 1.5배 (b) 위원회 안 비교에서 과반이 같은 방향 |
| D3 | 정부안은 같은 위원회 안에서도 의원안보다 빨리 상정된다 | 위원회 안 비교에서 과반이 정부 < 의원 |

- 보조(판정 없음): 소위에 상정된 법률안 중 같은 날 같은 위원회에서 같은 법의 다른 법률안과 함께 상정된 비율. D1이 맞다면 그 이유(같은 법끼리 묶여 상정됨)를 보여 주는 자료다

## 6. 바꾸는 조건과 한계

- 법 이름 꼬리 떼기 규칙이 맞지 않는 이름이 많으면(예: "…법 일부개정법률안(대안)" 같은 형태) 규칙을 고치고 이 문서에 기록한다
- 결과는 관련일 뿐 원인이 아니다. 예를 들어 "혼자" 법률안이 오래 기다리는 것이 관심을 덜 받아서인지, 내용이 새로워 검토가 더 필요해서인지는 이 데이터로 구분할 수 없다
- 법 이름은 공개 문서에 나열하지 않는다(쟁점 법안이 섞여 있음). 집단별 집계만 공개한다

### 집단별 (소위 회부 → 소위 상정)

| 특징 | 집단 | 법률안 | KM 중앙값 | 1년 안 상정 비율(보조) |
|---|---|---|---|---|
| 같은 법 법률안 수 | 1건(혼자) | 1,078 | 없음 | 39.8% |
| | 2～4 | 1,174 | 642일 | 42.7% |
| | 5～9 | 1,944 | 511일 | 45.6% |
| | 10～49 | 7,205 | 없음 | 41.4% |
| | 50건 이상 | 6,228 | 302일 | 52.0% |
| 법률안 종류 | 일부개정 | 16,403 | 567일 | 45.3% |
| | 제정 | 1,124 | 378일 | 49.7% |
| | 전부개정·폐지 | 102 | 203일 | 55.1% |
| 제안자 | 의원 | 17,161 | 531일 | 45.4% |
| | 정부 | 468 | 202일 | 53.4% |

- D1의 차이는 대부분 **50건 이상** 집단에서 온다. 혼자부터 10～49까지는 1년 안 상정 비율이 40～46%로 비슷하고, 50건 이상만 52%로 뚜렷이 빠르다. 즉 "같은 법 법률안이 많을수록 빠르다"는 단조로운 관계가 아니라 "아주 많은 법률안이 몰린 법은 빨리 다뤄진다"에 가깝다
- 보조 자료: 소위에 상정된 8,137건 중 **81.3%가 같은 날 같은 위원회에서 같은 법의 다른 법률안과 함께** 상정됐다. 소위는 법률안 한 건이 아니라 법 단위로 묶어서 다룬다

### 위원회 안 비교에서 생긴 문제: 중앙값이 없는 위원회

- 위원회 안 비교에서 **두 집단 모두 KM 중앙값이 없는(둘 다 절반 넘게 기다리는) 위원회**가 D1 5개, D2 3개, D3 1개였다. 5절 기준은 "같은 방향"을 엄격한 부등호로 정해, 이런 위원회는 "같은 방향 아님"으로 셌다. 판정은 기준대로 둔다
- 기준을 정할 때 이런 동점을 어떻게 볼지 정하지 않았다. 1016_09(T3)에 이어 두 번째다. 다음 결정 문서부터는 **동점·값이 없는 경우의 처리를 판정 기준에 함께 적는다**
- **결과를 본 뒤 추가한 보조 지표**(판정에 쓰지 않음): 중앙값 대신 늘 계산되는 "1년 안 상정 비율"로 위원회 안 비교를 다시 하면, 같은 방향인 위원회가 D1 13개 중 **10개**, D2 12개 중 7개, D3 7개 중 5개다. D1은 위원회 안에서도 대체로 같은 방향이라고 볼 수 있지만, 이 기준은 결과를 본 뒤 정한 것이라 판정으로 쓰지 않는다

### 교차 검증

- 법 이름·법률안 종류 규칙을 SQL 정규식으로 따로 작성하고, 집단별 건수·KM 중앙값·1년 안 상정 비율, 위원회 안 비교 위원회 수·같은 방향 수, 같은 날 함께 상정된 비율을 다시 계산 → 39항목 일치(`cross_check.py` ⑬, 전체 426항목)
- 처음 SQL에서 "1년 안 상정 비율"을 누적 생존율의 마지막 값이 아니라 첫 값으로 잘못 계산해 7항목이 어긋났다. SQL 쪽 오류로 확인해 고쳤다(분석 코드는 그대로)

### 결과에서 얻은 것

1. 소위 상정은 법 단위로 묶여 일어난다(81.3%). 같은 법에 법률안이 아주 많이 몰리면 빨리 다뤄지고, 그렇지 않으면 법률안 종류나 같은 법 법률안 수와 큰 관계가 없다
2. "제정법안이 더 오래 걸린다"는 예상은 맞지 않았다. 전체로는 오히려 제정법안이 빨랐지만 위원회마다 방향이 갈려 일관된 차이라고 하기 어렵다
3. 정부안이 빠른 것은 같은 위원회 안에서도 대체로 유지되지만(7개 중 4개, 보조 지표로 5개), 차이가 위원회마다 크다
4. 업무 관점: 대기 법률안을 관리할 때 "한 건씩"보다 "법 단위 묶음"으로 보는 것이 실제 처리 방식과 맞다. OCEL(1016_12)에서 이 묶음 구조를 직접 다룬다
